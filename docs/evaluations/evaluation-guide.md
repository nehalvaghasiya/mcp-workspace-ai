# Evaluation method and baseline

This is a deterministic **FakeLLM pipeline evaluation**, not a real-model reasoning benchmark. The curated routines and prompts are public and share the same fixture domain. Passing results establish routing, policy, references and file pipeline behavior for these cases; they do not establish general natural-language accuracy.

The guide's listed counts sum to 52, rather than its stated 58. [ADR 0008](../adr/0008-evaluation-accounting.md) records the correction. The [52 explicit cases](../../evaluations/datasets/) include expected states/tools, forbidden writes, source providers, artifact formats and ambiguity. `evaluations/datasets` links to the authoritative packaged resources under `evaluations/src/mcp_workspace_evaluations/datasets`.

## Resource and quality limits

A separate network-disabled Docker smoke run peaked at **237,375,488 bytes** cgroup memory under an 8 GiB limit; see [container-proof.json](../../demo/evidence/baseline/container-proof.json). This is one pre-reorganization synthetic run, not load testing or a physical 8 GB hardware benchmark. Native Office visual fidelity remains NOT_RUN; structural checks do not prove identical layout in every viewer.

Real-model reasoning/claim accuracy, model tokens/cost, actual Google behavior and public deployment are **NOT_RUN**. The configurable provider is covered by HTTP-stub tests for authorized context, typed calls, bounded errors and usage recording. Those tests are not model-quality scores.

## Reproduction

Run `make setup`, `make dev`, and then `make eval` in a second terminal. Evaluation requires a running mock API and FakeLLM, creates an isolated synthetic account per case, cancels waiting approvals, and removes local account data afterward. A failed case makes the command exit nonzero. The report is overwritten with the new actual run; retain it separately if comparing environments.

## Workspace organization

The same 52 case IDs and assertions are partitioned across `tool_selection`, `multi_step_workflows`, `authorization`, `document_generation`, `prompt_injection` and `ambiguity_and_errors` JSONL files. The installed evaluation package reads packaged data; it does not rely on a repository parent path. New reports are written to `evaluations/reports`, while the historical directory retains the prior measured run. Reorganization acceptance requires comparing case identities and assertions, not just counts.
